# Lab 4 Section 3.2 testing summary

The BCE `RecommendationEngine` control is represented by `calculateRecommendationScore()` and its candidate-ranking caller. Black-box tests cover SRS FR44–FR49 using equivalence classes and numerical boundaries: ratios 0/1, walking 799/800/801 m, ETA 0/15/60 min, missing history, missing real-time data, and rain/shelter combinations. The 1.1 rain factor and 800 m limit come from current implementation because the SRS does not specify their values.

White-box basis-path tests cover `rankCarparks()` (V(G)=6, six feasible basis paths) and `getHistoricalAvailabilityRatio()` (V(G)=5, five feasible basis paths). `getNearbyCarparks()` was inspected but its many independent service-failure branches made it less suitable for an auditable lab-sized graph. The CFGs count the chosen methods, treating called helpers as call nodes; helper-specific edge cases have extra existing tests. This is path coverage for the documented graphs, not instrumented statement coverage.

Ten black-box cases and eleven basis-path cases are mapped to existing automated tests, with overlap where a test serves both purposes. Seven existing scorer tests and three new scorer tests make ten. Existing rank tests cover all six method-level paths. Five existing historical tests plus two new query-failure tests make seven. The focused three-file run executed **29 tests**, all passing. The full repository run executed **300 backend** and **153 frontend** tests, all passing; typecheck and lint also passed. See [inputs and actual results](test_results.md).

Traceability: FR44 ratio inputs → BB01, BB08, BB09; FR45 historical reliability → WB-H1–H5 plus the existing invalid-row/insufficient-days tests; FR46 ETA weighting → BB01–BB04; FR47 walking score → BB01, BB03, BB04, BB08, BB09; FR48 base score → BB01–BB04; FR49 rain/shelter preference → BB05–BB06 and the existing rank rain test. Candidate exclusion and ordering → WB-R1–R6.

Limitations and findings: `calculateRecommendationScore()` accepts negative ETA and extrapolates an availability score above 1; BB10 documents this observed behaviour. `rankCarparks()` rejects negative ETA before calling it. No unsupported validation rule was added. The historical ratio test also documents that available lots can exceed total lots in currently accepted input. `getNearbyCarparks()` currently passes the current day/hour to historical lookup, although FR45 specifies the *estimated arrival* day/hour; this integration discrepancy was observed in source inspection, not exercised by the selected unit tests. No production logic was changed. Lab 4 Section 3.2 is completed for the selected control and methods; Sections 3.3 and 3.4 were not attempted.
